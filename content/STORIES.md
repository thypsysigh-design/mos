# 이야기 엑셀 관리

원본은 [stories.xlsx](stories.xlsx)입니다. 수정한 파일을 대화에 첨부하거나 저장소의 파일을 교체하세요. 게임 실행·빌드 때 반영하며, 기존 다운로드 HTML은 요청하실 때 다시 만듭니다. 이야기 내용·선택지·결과 문구는 이 파일에서 관리하고, 일반 화면 문구는 game-texts.xlsx에서 관리합니다.

## Stories: 등장과 내용

| 열 | 입력 방법 |
| --- | --- |
| ID | 고유한 영문 식별자. 예: forest_guest |
| 등장구분 | random: 무작위 이야기, start: 시작, ending: 마지막 이야기 |
| 등장가중치 | 0 이상 숫자. 무작위 이야기끼리 비율로 계산, 0이면 추첨 제외 |
| ko_title / ko_place / ko_text | 제목 / 장소 / 본문 |
| en_* / ja_* | 번역. 비어 있으면 해당 한국어 문구 사용 |

가중치가 1, 2, 1이면 **이야기 이벤트 안에서** 25%, 50%, 25%입니다. 25, 50, 25를 입력해도 같습니다. 확률은 가중치 ÷ 활성 무작위 이야기의 가중치 합계입니다. 이야기에는 재등장할 수 있으며 미방문 여부로 확률을 바꾸지 않습니다.

전투/이야기/상점의 전체 이벤트 비율(일반 구간 50%/30%/20%)과 고정 진행 날짜는 유지합니다. gate는 start, heart는 ending이며 이 두 ID와 구분을 유지하세요. 무작위 이야기는 최소 하나의 가중치가 0보다 커야 합니다.

## Choices: 선택지 3개

이야기ID마다 선택번호 **1, 2, 3**을 한 행씩 입력합니다.

- ko_label: 선택지 문구 / ko_hint: 선택 전 설명
- 판정스탯: 빈칸이면 항상 성공. mu(무), ji(지), de(덕), che(체), un(운) 중 하나면 능력치 판정
- 난이도: 주사위 1~6 + 해당 스탯이 이 값 이상이면 성공. 판정스탯이 비어 있으면 난이도도 빈칸 또는 0
- 비용: 선택할 때 지불하는 냥. 소지금이 부족하면 선택할 수 없음
- en_* / ja_*: 번역

## Effects: 선택 결과와 실제 효과

이야기ID + 선택번호 + 결과(success 또는 failure) 조합으로 한 행씩 입력합니다. 모든 선택지는 success가 필요하며, 능력치 판정이 있으면 failure도 필요합니다. 판정이 없으면 failure 행을 만들지 마세요.

| 열 | 효과 |
| --- | --- |
| ko_text | 선택 후 표시할 결과 문구 |
| 체력변화 / 정신력변화 | 양수: 회복, 음수: 감소. 0~최대치 범위로 제한 |
| 냥변화 / 유물변화 | 양수: 획득, 음수: 감소. 0 미만이 되지 않음 |
| 획득아이템ID | items.xlsx의 ID. 빈칸이면 지급 없음 |
| 아이템분실 | yes: 보유 아이템 중 무작위 1개 분실 / no 또는 빈칸: 없음 |
| 상태효과 | blessing: 산신의 가호 / curse: 원한의 저주 / 빈칸: 없음 |
| 효과전투횟수 | 상태효과가 적용될 전투 수(1~99). 상태효과가 없으면 빈칸 또는 0 |
| 기록플래그 | 이야기·결말 조건에 쓰는 영문 기록. 기존 child, truth, map, freed 등은 기존 결말과 연결됨 |
| 탕약변화 | 산삼 탕약 수량 증감. 보통은 획득아이템ID 사용 권장 |

체력 0이면 모험이 종료됩니다. 무작위 분실할 물건이 없으면 최대 3냥을 잃습니다. 이미 가진 장비를 다시 받으면 판매가만큼 냥을 받습니다. 같은 상태효과를 다시 얻으면 입력한 전투 횟수로 갱신합니다. 효과는 체력·정신력·냥·유물·탕약 변화 → 아이템 획득 → 분실 → 상태효과 순서로 적용됩니다.

결과 문구와 선택 전 설명은 자유롭게 작성하므로 수치 효과와 일치하도록 함께 수정하세요. 실제 효과는 효과 열의 값으로 결정됩니다.

## 새 이야기 추가 예

1. Stories에 ID `forest_guest`, 등장구분 `random`, 등장가중치 `2`와 제목·장소·내용을 추가합니다.
2. Choices에 이야기ID `forest_guest`로 선택번호 1, 2, 3을 추가합니다.
3. Effects에 각 선택의 success를 추가합니다. 판정스탯을 입력한 선택은 failure도 추가합니다.
4. 예: 첫 선택 success에 획득아이템ID `potion`, 두 번째 success에 정신력변화 `5`, 세 번째 success에 상태효과 `curse`, 효과전투횟수 `3`.

## 마지막 이야기의 기존 조건

heart의 내용에 있는 `{value1}`과 `{value2}`는 기존 이야기 기록에 따라 삽입되는 문구입니다. 첫 선택의 힌트에 있는 `{value1}`은 필요한 유물 수(2 또는 3)로 바뀝니다. 두 번째 선택은 동행 기록이 있으면 판정을 생략하고 `ko_help_hint`(및 번역)를 표시합니다. 결말 선택 번호별 결말 연결과 유물 요구 조건은 기존 게임 규칙을 유지합니다. 이 조건 자체를 바꾸려면 개발 작업이 필요합니다.

기존 이야기 ID는 저장 데이터와 연결되므로 삭제하거나 바꾸지 않는 편이 좋습니다. 무작위 등장을 멈추려면 가중치를 0으로 바꾸세요. 새 전투나 상점은 이야기 파일에서 만들지 않습니다.

## 개발자 명령

- `npm run stories:import`: 엑셀을 src/data/stories.json으로 반영
- `npm run stories:check`: 원본과 생성 파일 일치 검사
- 시작·실행·빌드 전에 자동 반영. 테스트 전에 원본 일치 검사

수식, 중복 ID, 빠진 선택지·성공/실패 결과, 잘못된 아이템과 상태효과, 음수 가중치는 반영 단계에서 거부합니다. 생성 JSON을 직접 수정하지 마세요.
